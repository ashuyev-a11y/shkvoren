# Правила для coding-agent

## Архитектурные ограничения

1. **Фронтенд**: Next.js с App Router
2. **Типизация**: TypeScript строго обязательна
3. **Стилизация**: Tailwind CSS с использованием токенов дизайна
4. **Состояние**: Zustand для глобального состояния
5. **API**: RESTful endpoints через Next.js API routes
6. **База данных**: PostgreSQL (Supabase)
7. **Деплой**: Vercel

## Дизайн-система ШКВОРЕНЬ как source of truth

1. Все визуальные решения должны строго соответствовать `tokens.json`
2. Все тексты должны соответствовать голосу бренда из `README (3).md`
3. Компоненты должны быть реализованы согласно принципам из фирменного стиля
4. Любые изменения в дизайне требуют обсуждения

## Правила работы с данными

1. **Источник правды**: База данных PostgreSQL
2. **Запрещено**: Придумывать данные или значения
3. **Обязательно**: Использовать только существующие данные из базы
4. **Форматирование**: Все числовые значения должны использовать форматирование из токенов (пробелы как разделители тысяч, символ ₸ для тенге)

## Правила изменения файлов

1. **README и tokens.json**: НЕЛЬЗЯ изменять без явного указания
2. **SQL схема**: Может быть дополнена, но не изменена без веской причины
3. **Код**: Все изменения должны сопровождаться комментариями
4. **Компоненты**: Должны строго следовать принципам дизайна

## Обязательные проверки после изменений

1. Все цвета соответствуют токенам
2. Все типографические стили соответствуют токенам
3. Все отступы используют токены
4. Все радиусы соответствуют токенам
5. Тексты соответствуют голосу бренда
6. Работа функциональности на мобильных устройствах
7. Доступность (accessibility) компонентов

## Запрет на выдумывание данных

1. **Цены**: Только из базы данных или Excel
2. **Названия товаров**: Только из базы данных или Excel
3. **Артикулы**: Только из базы данных или Excel
4. **Применимость**: Только из базы данных или Excel
5. **Фото**: Только реальные фотографии товаров

## Правила завершения задач

1. Задача считается выполненной только при прохождении всех acceptance criteria
2. Код должен быть протестирован вручную
3. Все визуальные элементы должны соответствовать фирменному стилю
4. Документация должна быть обновлена при необходимости
5. Нельзя оставлять "заглушки" или временные решения
