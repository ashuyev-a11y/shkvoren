# Документация ШКВОРЕНЬ — указатель и приоритет

## Порядок старшинства (что важнее при противоречии)

1. **`docs/decisions.md`** — зафиксированные решения. Старше всего остального.
2. **`tokens.json`** — все визуальные значения. Изменять только по явному указанию.
3. **`README (3).md`** (корень) — голос бренда и правила интерфейса.
4. **`AGENTS.md`** — правила работы агентов.
5. **`docs/data-model.md`** и **`docs/technical-spec.md`** — **переписаны**
   (задачи №2 и №3), действующий контракт кода.
   **`docs/product-spec.md`**, **`docs/implementation-plan.md`** — спецификации
   первой итерации (Qwen), **устарели частично**, см. таблицу ниже.
6. **`schema.sql`** (корень) — схема Supabase. **Заморожена**: по решению 1
   (`decisions.md`) мастер-источник — Google-таблица, Supabase в MVP не используется.

## Источники данных

| Что | Где | Роль |
| --- | --- | --- |
| Каталог, цены, остатки | Google-таблица (сервисный аккаунт, только сервер) | Единственный мастер |

### Что из хэндофа не сделано и почему

| Пункт хэндофа | Почему не сделано |
| --- | --- |
| Кросс-номера в карточке | такой колонки в таблице нет, показывать нечего |
| Фото позиции, галерея | фото нет ни у одной из 278 позиций (решение 15) |
| Правка товара и заказа в админке | источник — таблица (решение 1); колонок статуса и журнала изменений в ней нет |
| Экран `/admin/sync` | синхронизации в архитектуре нет, есть сброс кэша кнопкой |
| `/order/:number/done`, `/order/:number/print` | номера последовательны, перебором открывался бы чужой заказ с телефоном |
| Номер заказа на бланке | присваивается листом «Заказы» при записи, бланк печатается до отправки |
| Hex-цвета из хэндофа | цвет только через токены, гейт `hex-color` не пропускает |
