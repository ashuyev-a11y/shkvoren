# Модель данных ШКВОРЕНЬ

Контракт между Google-таблицей и приложением. Основан на решениях `docs/decisions.md`
и на фактическом содержимом снимка `Запчасти_с_ценами_рынка (2).xlsx` (корень репозитория).

Все числа в документе получены разбором снимка и сверены с листом «Сводка» самой таблицы.
**Ничего не додумано.** Если поля нет в источнике — в документе стоит «нет в данных»,
а не выдуманное значение.

### Следствия

- **`cost_price` (G) в источнике пуста у всех 278 позиций.** Поле остаётся запрещённым
  к выдаче наружу (решение 5) на случай, если оператор начнёт её заполнять.
- **Колонки C, F, J, P пусты полностью.** В UI не используются. Не выводить пустые

## 3. Ключ позиции

**Решение 9:** ключ — отдельная колонка `ID`, сквозная нумерация.

### Почему не артикул

Артикул на роль ключа не годится — проверено на данных:

- нет у 93 позиций из 278 (33%);
- **повторяется у разных товаров** — 3 случая:

  | Артикул | Позиция 1 | Позиция 2 |
  | --- | --- | --- |
  | `211009070` | Комплект прокладок масляного поддона ЗМЗ 417 — 2 000 ₸ | Высоковольтные провода (комплект) — 4 000 ₸ |
  | `521701111` | Шестерня второй передачи, ГАЗ — 20 000 ₸ | Шестерня второй передачи, ГАЗ 53 — 25 000 ₸ |
  | `4171000150` | Комплект прокладок на ЗМЗ 417 — 15 000 ₸ | Комплект прокладок УМЗ 4178 — 1 000 ₸ |

Связка «наименование + применимость» тоже не уникальна (4 пары, например два разных
сальника коленвала ВАЗ по размерам `40x56x7.5` и `80x100x10`).

### Порядок заведения

1. В лист `Запчасти` добавляется колонка **AI** с заголовком `ID`.
2. Заполняется значениями `1..278` **в текущем порядке строк, один раз**.
3. Далее: новая позиция получает `max(ID) + 1`. **ID никогда не переиспользуется**
   и не пересчитывается — даже если строку удалили или переставили.
4. Колонка скрывается в интерфейсе таблицы.

> **Блокирует задачу №5.** Колонка `ID` на момент написания документа в таблице
> отсутствует. Импортёр не запускать до её заведения.

**Строка без `ID` — ошибка импорта**, а не повод сгенерировать ID на лету:
иначе номер «уедет» при следующей сортировке таблицы, и старые заказы будут ссылаться
не на те позиции.

## 4. Нормализация полей

Применяется при чтении, **в таблицу не записывается** (оператор правит вручную).

### `title` (B)

- `trim` и схлопывание двойных пробелов. **38 названий из 278** имеют хвостовые пробелы
  (`"Тормозной суппорт УАЗ "`, `"Задние тормозные колодки "`).
- Регистр **не менять**: в источнике встречается и «муфта скользящая фланца»,
  и «Муфта КПП 3-4 передачи». Приводить к общему виду — значит редактировать данные.

### `price` (H), `qty` (K)

- Только целые. В данных дробных нет: цены 50..300 000 ₸, остатки 1..214.
- Пустое или нечисловое значение — **ошибка строки**, позиция не попадает на витрину.
  Подстановка нуля запрещена.
- Формат вывода — из `tokens.json`: пробел-разделитель тысяч, `₸`, табличные цифры
  (`17 500 ₸`).

### `category` (E)

Заполнена у всех 278. Ровно 8 значений, регистр единый — нормализация не нужна:

| Категория | Позиций |
| --- | --- |
| Подвеска | 143 |
| Двигатель | 65 |
| Тормоза | 26 |
| Электрика | 16 |
| Другое | 15 |
| Кузов | 9 |
| Фильтры | 2 |
| Расходники | 2 |

Список фильтра в UI строится **из данных**, а не из константы в коде.
Порядок — по убыванию количества, как в таблице выше.

## 5. Артикул: три разных вида значений

Колонка A содержит **не только каталожные номера**. Разбор всех 185 значений:

| Вид | Кол-во | Примеры | Как показывать |
| --- | --- | --- | --- |
| Цифровой номер, 4–13 знаков | 127 | `4693501070`, `37413502013` | моноширинный, копируемый |
| Цифровой, **14–18 знаков** | 29 | `316000350108400`, `469003501041496` | как есть, **не разбивать** |
| **Размер**, не номер | 24 | `42x68x16.4`, `95х130х12х17.5` | как есть, не моноширинным ярлыком «номер» |
| Смешанный / уже с дефисами | 5 | `0469-00-1602558-00`, `42.3708000-01`, `К126Г`, `6305n` | как есть |

### Правило отображения (решение 11)

```
если значение пустое            → «номер не указан» (ink-muted), поле не пустое
если значение — размер          → показать как есть, подпись «размер»
если 14+ знаков или смешанное   → показать как есть, без дефисов
иначе                           → показать как есть
```

**Дефисы не расставляются автоматически ни при каких условиях.** В снимке нет
ни одной позиции, для которой разбивка подтверждена источником; 5 значений уже
содержат дефисы от оператора — они сохраняются.

Классификация «это размер» — регулярное выражение `^\d+[.,]?\d*\s*[xх]\s*\d`
(латинская `x` — 26 значений, кириллическая `х` — 1).

### Нормализация для поиска (`article_norm`)

Поиск работает по отдельному вычисляемому значению:

1. верхний регистр;
2. удалить всё, кроме букв и цифр (дефисы, точки, пробелы, `x`/`х` в размерах);
3. **кириллица → латиница** для визуально совпадающих букв:
   `А→A О→O Р→P С→C Е→E Т→T Н→H К→K М→M В→B Х→X У→Y`.

Третий пункт обязателен: в данных 8 артикулов с кириллицей (`53А170201002`,
`К126Г`, `Г25000370120001`, `ПФ13011`…) и 27 с латиницей. Механик, набирающий
`53A170201002` латиницей, обязан найти позицию с кириллической `А`.

Поиск сопоставляет: точное совпадение `article_norm` → вхождение подстроки
(от 4 знаков) → триграммное совпадение по `title`.

## 6. Применимость

**Решение 10: строка хранится как есть, автоматический парсинг запрещён.**

В данных 17 вариантов написания:

| Значение | Позиций | | Значение | Позиций |
| --- | --- | --- | --- | --- |
| `УАЗ` | 127 | | `Газель` | 11 |
| `УАЗ/ ГАЗ` | 35 | | `Уаз` | 9 |
| `ГАЗ` | 28 | | `УАЗ Буханка` | 9 |
| `УАЗ/ГАЗ` | 22 | | `ВАЗ` | 6 |
| `ГАЗ 53` | 16 | | `УАЗ/ ГАЗ/ ВАЗ` | 2 |
| *(пусто)* | 7 | | `ЗИЛ`, `КамАЗ`, `МАЗ`, `ГАЗ 66,3308`, `УАЗ/ ВАЗ`, `ГАЗ ` | по 1 |

Различаются регистром (`УАЗ`/`Уаз`), пробелом после слэша (`УАЗ/ГАЗ`/`УАЗ/ ГАЗ`)
и хвостовым пробелом (`ГАЗ `).

**На витрине выводится исходная строка**, приведённая только `trim`.
Замена `«УАЗ/ ГАЗ»` на `«УАЗ · ГАЗ»` по брендбуку — **отдельное решение оператора**
в самой таблице, приложение текст не переписывает.

Справочники `vehicle_models` / `engines` / `part_fitment` из `schema.sql` в MVP
не используются (схема заморожена, см. `docs/README.md`).

## 7. Фильтр по марке

**Решение 7: показываем только ГАЗ и УАЗ.**

Принадлежность определяется **вхождением подстроки** в `fitment_raw`
после приведения к верхнему регистру и замены `Ё→Е`:

```
содержит "УАЗ" → марка УАЗ
содержит "ГАЗ" → марка ГАЗ
обе          → обе метки
```

`«Газель»` содержит `ГАЗ` — попадает в ГАЗ корректно (11 позиций).
`«ГАЗ 53»`, `«ГАЗ 66,3308»` — тоже.

### Результат на данных

| Группа | Позиций | На витрине |
| --- | --- | --- |
| Есть ГАЗ или УАЗ | **262** | да |
| Применимость пуста | **7** | **см. открытый вопрос №1** |
| Только ВАЗ / ЗИЛ / КамАЗ / МАЗ | **9** | нет |

Скрываемые 9 позиций: 6 ВАЗ (сальники коленвала, крестовины Нива и Жигули,
подвесной подшипник, сальники клапанов), ЗИЛ (шестерня коленвала),
КамАЗ и МАЗ (сальники ТНВД).

Фильтр применяется **при чтении на сервере**: скрытые позиции не уходят в браузер.

## 8. Лист «Заказы»

Создаётся в той же таблице. Приложение **только дописывает строки**, никогда не правит
и не удаляет (решение 2).

| Кол. | Заголовок | Содержимое | Пример |
| --- | --- | --- | --- |
| A | Номер заказа | `ШКВ-` + 4 цифры (решение 4) | `ШКВ-0001` |
| B | Дата и время | ISO 8601, часовой пояс Уральска | `2026-09-20T14:31:05+05:00` |
| C | Телефон покупателя | как ввёл покупатель | `+7 777 123 45 67` |
| D | Позиций | количество строк заказа | `3` |
| E | Итого, ₸ | целое | `47500` |
| F | Состав | `ID×кол-во` через `;` | `12x2; 48x1; 105x4` |
| G | Состав (читаемо) | по строке на позицию | `4693501070 — Задний тормозной барабан, 2 шт × 20 000 = 40 000` |
| H | Статус | `новый` при создании | `новый` |
| I | Предложено за заказ, ₸ | целое или пусто (решение 18) | `25000` |
| J | Итого по прайсу, ₸ | целое, всегда заполнено | `47500` |
| K | Комментарий | текст до 300 символов или пусто (решение 18.1) | `Заберу в субботу` |

### Комментарий к заказу (решение 18.1)

Необязательное поле на чекауте. Переносы строк схлопываются в пробел, крайние
пробелы снимаются, длина обрезается до 300 символов — заказ из-за комментария
не отклоняется. Пустой комментарий оставляет K пустой и не добавляет строку
в сообщения. Заполненный идёт последней строкой `Комментарий: <текст>`
и в WhatsApp, и в Telegram (уведомление собирается своей функцией,
поэтому строка передаётся туда явно).

### Предложение цены (решение 18)

Колонки I и J появились вместе с торгом. Разделение такое:

- **E «Итого»** — сумма, которую покупатель предлагает заплатить: предложение
  за заказ, если оно есть, иначе сумма строк с учётом построчных предложений,
  иначе прайс. Это та цифра, которую продавец обсуждает.
- **J «Итого по прайсу»** — та же сумма по ценам таблицы. Нужна, чтобы видеть,
  от чего торгуются, не пересчитывая состав вручную.
- **I** пусто, если покупатель не называл сумму за весь заказ.

Построчные предложения живут в составе:

- **F** — `ID×кол-во@предложенная цена`: `1x2@15000; 2x1`. Без `@` торга по
  позиции не было.
- **G** — к строке дописывается `(предложено: 15 000 ₸/шт = 30 000 ₸)`.

Предложение за заказ перекрывает построчные при подсчёте E, но сами построчные
из F и G не пропадают: видно, с чего покупатель начал.

Сайт ничего не подтверждает и не пересчитывает остаток: решение по цене
принимает продавец в переписке.

### Номер заказа

`ШКВ-0001`, инкремент = следующая свободная строка листа (решение 4).
Номер вычисляется **на сервере непосредственно перед записью**.

Гонка при одновременных заказах маловероятна (один магазин, редкие заявки), но
номер обязан браться из фактического количества строк листа на момент записи,
а не из счётчика в приложении.

### Порядок операций

```
1. валидация корзины и телефона
2. запись строки в лист «Заказы»   ← заказ существует с этого момента
3. редирект на wa.me с текстом (решение 12)
```

Если шаг 2 не удался — **редиректа нет**, показывается ошибка.
Заказ, не записанный в таблицу, не существует.

## 9. Публичный контракт

**Решение 5.** Ответ любого публичного эндпоинта содержит **ровно** эти поля:

```ts
type PublicPart = {
  id: number;            // AI
  title: string;         // B, trim
  article: string | null;// A, null если пусто
  articleKind: 'number' | 'size' | 'none';
  fitment: string | null;// D, trim
  brands: ('ГАЗ' | 'УАЗ')[];
  category: string;      // E
  price: number;         // H, целое ₸
  qty: number;           // K, целое
};
```

Запрещено к выдаче наружу: `cost_price` (G), `market_price` (AC), `market_delta` (AG),
`price_note` (AH), источники цен (R–AA), «Поступило» (I), «Продано» (J).

Проверяется автотестом: ответ публичного эндпоинта не должен содержать подстрок
`cost`, `закупоч`, `рынк`, `market`.

## 10. Идемпотентность чтения

Чтение каталога — операция без записи, поэтому «идемпотентность импорта» в смысле
старой Supabase-архитектуры неприменима. Вместо неё:

| Правило | Проверка |
| --- | --- |
| Кэш чтения 3–5 минут + кнопка «Обновить сейчас» в админке (решение 1) | ручная |
| Строка без `ID` → ошибка, позиция не показывается, счётчик ошибок в админке | автотест |
| Строка без `price` или `qty` → та же ошибка | автотест |
| Расхождение контрольных сумм (§1) → предупреждение в админке | автотест |
| Позиция, исчезнувшая из таблицы, исчезает с витрины после сброса кэша | ручная |
