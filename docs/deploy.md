# Запуск продакшена

Порядок старшинства документов — `docs/README.md`. Этот файл описывает только
последовательность действий: что завести, куда положить и как проверить.

---

## 1. Что нужно завести до деплоя

| № | Что | Кто делает | Без этого |
| --- | --- | --- | --- |
| 1 | Колонка `ID` в листе «Запчасти» (колонка AI, сквозные числа 1..N) | владелец таблицы | каталог пуст: ключ позиции взять неоткуда (решение 9) |
| 2 | Лист «Заказы» с заголовками A..J по `data-model.md` §8 | владелец таблицы | заказ не записывается, покупателю отдаётся 502 |
| 3 | Сервисный аккаунт Google + доступ к таблице | владелец Google-аккаунта | нет чтения и записи |
| 4 | Репозиторий на GitHub | владелец | нечего подключать к Vercel |
| 5 | Проект в Vercel | владелец | негде размещать |

### Колонка ID

В строке 1 колонки AI — заголовок `ID`. Ниже, со строки 2, сквозные целые
числа. Номер **не переиспользуется**: удалили позицию — число остаётся
пропущенным. Дубликат ID даёт `SheetIssue` уровня `error`, позиция не
показывается, оператор видит это в админке.

### Лист «Заказы»

Имя листа — ровно `Заказы` (или другое, тогда его нужно указать в
`SHEET_ORDERS_NAME`). Строка 1 — заголовки:

```
Номер заказа | Дата и время | Телефон покупателя | Позиций | Итого, ₸ | Состав | Состав (читаемо) | Статус
```

Приложение только дописывает строки, никогда не правит и не удаляет
(решение 2).

### Сервисный аккаунт Google

1. console.cloud.google.com → новый проект (или существующий).
2. APIs & Services → Library → включить **Google Sheets API**.
3. IAM & Admin → Service Accounts → Create service account.
4. У созданного аккаунта: Keys → Add key → Create new key → **JSON**.
5. Открыть Google-таблицу → «Настройки доступа» → добавить адрес вида
   `имя@проект.iam.gserviceaccount.com` с правом **Редактор**.
   Право на запись обязательно: приложение дописывает лист «Заказы».

Из скачанного JSON нужны два поля: `client_email` и `private_key`.

## 2. Переменные окружения

Полный список с комментариями — в `.env.example`. В Vercel заводятся все
двенадцать, для окружений Production, Preview и Development.

| Переменная | Откуда берётся |
| --- | --- |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | поле `client_email` из JSON ключа |
| `GOOGLE_PRIVATE_KEY` | поле `private_key` из JSON ключа |
| `SHEET_ID` | из адреса таблицы: `docs.google.com/spreadsheets/d/<SHEET_ID>/edit` |
| `SHEET_PARTS_NAME` | `Запчасти`, если лист не переименован |
| `SHEET_ORDERS_NAME` | `Заказы`, если лист не переименован |
| `ADMIN_PASSWORD` | придумывается владельцем, хранится в менеджере паролей |
| `ADMIN_SESSION_SECRET` | `openssl rand -hex 32` |
| `NEXT_PUBLIC_WHATSAPP_NUMBER` | номер продавца, только цифры, без `+` и пробелов |
| `NEXT_PUBLIC_SELLER_ADDRESS` | адрес точки на Салеме для летерхеда бланка |
| `NEXT_PUBLIC_SELLER_PHONE` | телефон продавца для летерхеда |
| `TELEGRAM_BOT_TOKEN` | токен бота от `@BotFather` |
| `TELEGRAM_CHAT_ID` | идентификатор чата заказов; у групп он отрицательный |

### `GOOGLE_PRIVATE_KEY` — единственное место, где легко ошибиться

В JSON ключ записан с настоящими переводами строк. В переменную окружения
он кладётся **одной строкой**, где переводы заменены на два символа `\n`:

```
-----BEGIN PRIVATE KEY-----\nMIIEvQIBADANBgkq...\n-----END PRIVATE KEY-----\n
```

`lib/sheets.ts` разворачивает `\n` обратно при чтении. Если вставить ключ
с настоящими переносами, Vercel примет значение, но подпись JWT не соберётся
и каталог отдаст «временно недоступен».

Получить готовую строку из JSON:

```bash
node -e "console.log(JSON.stringify(require('./ключ.json').private_key))"
```

Скопировать без внешних кавычек.

### Telegram: куда приходят уведомления о заказах

Решение 17: переход в WhatsApp не отправляет сообщение за покупателя, поэтому
о новом заказе продавца извещает бот. Порядок такой:

1. `@BotFather` → `/newbot` → получить токен.
2. Добавить бота в рабочую группу.
3. Узнать `chat_id`: отправить в группу любое сообщение и открыть
   `https://api.telegram.org/bot<токен>/getUpdates` — идентификатор
   в поле `message.chat.id`, у групп со знаком минус.
4. Проверить канал до деплоя:

```bash
curl -s -X POST "https://api.telegram.org/bot<токен>/sendMessage" \
  -H "Content-Type: application/json" \
  -d '{"chat_id":"<chat_id>","text":"проверка"}'
```

Пока переменные не заведены, `notifyNewOrder` пишет в лог «Telegram
не настроен» и выходит. Заказы при этом оформляются как обычно:
уведомление — дополнительный канал, а не часть потока заказа.

**Грабли CLI:** `vercel env add <ключ> preview` бесконечно переспрашивает
ветку — не помогают ни `--yes`, ни `--value`. Для Preview переменная
заводится только через API:

```bash
curl -s -X POST "https://api.vercel.com/v10/projects/<projectId>/env?teamId=<teamId>" \
  -H "Authorization: Bearer <токен>" -H "Content-Type: application/json" \
  -d '{"key":"TELEGRAM_CHAT_ID","value":"...","type":"encrypted","target":["preview"]}'
```

### Последние две переменные

`NEXT_PUBLIC_SELLER_ADDRESS` и `NEXT_PUBLIC_SELLER_PHONE` — открытый вопрос №4
в `docs/README.md`. Пока они пусты, летерхед бланка показывает только название
«ШКВОРЕНЬ» без адреса и телефона. Это не ошибка сборки: придумывать адрес
запрещено (`AGENTS.md`), поэтому строка просто не печатается.

## 3. Деплой

```bash
git remote add origin https://github.com/<аккаунт>/shkvoren.git
git push -u origin main
```

Затем в Vercel: Add New → Project → выбрать репозиторий.

Настройки определяются автоматически и менять их не нужно:

| Параметр | Значение |
| --- | --- |
| Framework | Next.js |
| Build Command | `npm run build` (предварительно генерирует `styles/tokens.css`) |
| Install Command | `npm install` |
| Output | `.next` |
| Node.js | 22.x или новее |

`styles/tokens.css` генерируется скриптом `prebuild` из `tokens.json`,
в репозитории он отмечен в `.gitattributes` как генерируемый и руками
не правится.

## 4. Проверка после первого деплоя

Сначала локально, с теми же значениями в `.env.local`:

```bash
node --env-file=.env.local scripts/check-sheet.mjs
```

Скрипт печатает контрольные суммы, список проблем и распределение по маркам.
Расхождение с листом «Сводка» видно сразу, до открытия витрины.

Затем на рабочем адресе:

| Шаг | Ожидание |
| --- | --- |
| Главная | список позиций, число совпадает со «Сводкой» за вычетом чужих марок |
| Поиск `3501` | находит позиции с номером `4693501070` |
| Фильтр ГАЗ / УАЗ | список сокращается, позиции без применимости уходят |
| Добавить позицию, `/cart` | степпер не даёт превысить остаток |
| Отправить без телефона | подпись под полем, запрос не уходит |
| Отправить с телефоном | новая строка в листе «Заказы», номер `ШКВ-0001`, открывается WhatsApp |
| `/print` | бланк А4, шапка и кнопки на печать не попадают |
| `/admin` | редирект на вход; после пароля — таблица и контрольные суммы |
| «Обновить сейчас» | время чтения меняется, правка в таблице видна сразу |

Первый заказ имеет смысл сделать на себя и удалить строку из листа вручную:
нумерация считается от числа строк, следующий заказ снова получит `ШКВ-0001`.
Лучше оставить тестовую строку и начать боевые заказы с `ШКВ-0002`.

## 5. Что в продакшене не работает по замыслу

- **Фото позиций** — их нет ни у одной из 278 строк (решение 15).
- **Кросс-номера** — колонки в таблице нет.
- **Правка каталога из админки** — правка идёт в Google-таблице (решение 1).
- **Резерв товара** — заказ ничего не резервирует до подтверждения по телефону.
- **Онлайн-оплата** — оплата на месте (решение 3).
- **Тёмная тема** — токены заведены, переключатель вне MVP.
