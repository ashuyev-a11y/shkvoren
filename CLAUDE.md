## 1. Что это

Опт-витрина новых запчастей ГАЗ и УАЗ в Уральске. Один магазин, один
оператор (Дмитрий), распродажа склада по себестоимости. Розницы нет,
ценовой уровень один (решение 0).

Путь покупателя:

```
каталог → поиск → [предложить свою цену] → корзина → телефон, комментарий
  → заказ пишется в лист «Заказы» → ссылка WhatsApp (покупатель жмёт «отправить»)
                                  → уведомление продавцу в Telegram
  → печатный бланк A4
```

**Боевой адрес:** https://shkvoren-mu.vercel.app
**Админка:** https://shkvoren-mu.vercel.app/admin (пароль — `ADMIN_PASSWORD` в `.env.local`)

## 2. Как устроено

| Слой | Чем сделан |
| --- | --- |
| Фронтенд | Next.js 15.5, App Router, React 19, TypeScript strict |
| Стили | Tailwind v4, цвета только через CSS-переменные из `tokens.json` |
| Состояние | Zustand + `persist` (корзина в `localStorage`, ключ `shkvoren-cart`) |
| Данные | Google-таблица через Sheets API, сервисный аккаунт, только сервер |
| Уведомления | Telegram Bot API (`lib/telegram.ts`) |
| Деплой | Vercel, продакшен из `main` — **только вручную через API** (§4) |

Базы данных нет. `schema.sql` заморожен: мастер — Google-таблица (решение 1).
`AGENTS.md` про PostgreSQL/Supabase в этой части недействителен (`docs/README.md`).

Библиотека `googleapis` не используется: JWT RS256 подписывается через
`node:crypto`, запросы — обычный `fetch` (`lib/sheets.ts`).

### Лист «Заказы», A1…K1 (сетка ровно 11 колонок)

```
A Номер заказа | B Дата и время | C Телефон покупателя | D Позиций | E Итого, ₸
F Состав | G Состав (читаемо) | H Статус | I Предложено за заказ, ₸
J Итого по прайсу, ₸ | K Комментарий
```

- E — действующий итог (с учётом торга), J — итог по прайсу, I — сумма
  «за весь заказ», если покупатель её предложил.
- F — машинный состав `id x qty` или `id x qty @ предложенная_цена`
  (пример `9x2@200`), подробно — `docs/data-model.md` §8.
- K — комментарий, до 300 символов, переносы схлопнуты в пробел.
- **Новая колонка = расширить сетку** (`appendDimension`), иначе запись
  за край вернёт 400. Диапазон записи — в `lib/sheets.ts` (`A:K`).

Номер `ШКВ-0001` вычисляется из фактического числа строк непосредственно
перед записью. Сейчас в листе ШКВ-0001 и ШКВ-0002 (настоящие, телефон
владельца), следующий заказ получит ШКВ-0003.

### Временные скрипты к живой таблице

Писать `_peek.mjs` в корне, запускать
`node --env-file=.env.local _peek.mjs`, **удалять сразу после запуска**.
Импортировать `lib/sheets.ts` нельзя (`server-only`) — JWT собирается
в самом скрипте через `createSign('RSA-SHA256')`. Скрипты удаляются,
в репозитории их нет; шаблон: header `{alg:'RS256',typ:'JWT'}`, claims
`{iss: GOOGLE_SERVICE_ACCOUNT_EMAIL, scope: 'https://www.googleapis.com/auth/spreadsheets',
aud: 'https://oauth2.googleapis.com/token', iat, exp: iat+3600}`, подпись
ключом `GOOGLE_PRIVATE_KEY.replace(/\\n/g, '\n')`, обмен на токен —
`POST https://oauth2.googleapis.com/token` с
`grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer`.

Удаление тестовых строк из «Заказы»: перед `deleteDimension` сверить
номер заказа **и** телефон, чужие строки не трогать. Тестовые заказы
шлются с телефоном `+7 777 000 00 00`.

### Торг — как устроен (решения 18, 18.1)

- **Где:** строка каталога, карточка товара, строка корзины (по позиции)
  и корзина — «сумма за весь заказ». Везде один компонент `OfferPrice`:
  по умолчанию свёрнутая ссылка «Предложить свою цену».
- **До добавления в корзину** цена живёт в локальном состоянии
  (`lib/offer.ts`, `usePartOffer`) и уходит вместе с позицией
  через `setQty(part, qty, offeredPrice)`. **После** — правится в позиции
  корзины (`setOfferedPrice`). Третий аргумент `setQty`: `undefined` —
  не трогать, `null` — снять.
- Валидация: целое > 0. Отсечки «не ниже прайса» нет намеренно (решение 0).
- Сумма за заказ побеждает построчные предложения, но построчные всё равно
  уходят в текст, в F/G листа и в бланк.
- Прайс хранится рядом, не заменяется. `cartTotal` — по прайсу,
  `effectiveCartTotal(items, offeredTotal)` — действующий.
- WhatsApp: строки `(предложено: X ₸/шт)`; при торге два итога —
  «Итого по прайсу» и «Итого (предложение покупателя)». **Без торга и без
  комментария текст посимвольно прежний** (решение 12, есть тест).
- Telegram: первая строка `💬 Покупатель предложил цену` (эмодзи только тут).

### Комментарий к заказу (решение 18.1)

Поле в корзине под телефоном, `COMMENT_MAX = 300`, счётчик. Хранится
в корзине (persist), сбрасывается `clear()`. Сервер (`normalizeComment`)
схлопывает переносы, обрезает, заказ не отклоняет. Непустой — последней
строкой `Комментарий: …` в WhatsApp и Telegram и в колонке K.

**Расхождение с постановкой:** §18.1 утверждает, что Telegram строится из
текста WhatsApp. Это не так — `buildNotification` собирает текст сам,
поэтому комментарий туда передаётся явно; тест проверяет совпадение строк.

Unit-тесты «карточки» из задачи 15 вызывали только стор корзины и не

### Урок `cfec714`

В `ProductRow` обёртка кнопок имеет `md:contents`, и её `z-10` на десктопе
не действует — растянутая ссылка строки (`before:absolute inset-0`)

- Скриншотов экранов нет (`docs/design/` пуст) — вёрстка по тексту.

### Эксплуатация

- Цены и остатки правятся **только в Google-таблице**.
- Кэш каталога — 4 минуты; «Обновить сейчас» в админке сбрасывает.
- Новая позиция получает `ID = max(ID) + 1`, номер не переиспользуется.
- Строка без `ID` на витрину не попадает, админка покажет её в проблемах.

## 7. Правила, которые нельзя нарушать

Порядок старшинства документов (`docs/README.md`):

```
decisions.md > tokens.json > README (3).md > AGENTS.md > спеки
```

Спека правится под решение, а не наоборот. Если постановка задачи
расходится с кодом — написать об этом в отчёте, а не молча подогнать.

- **Данные не выдумываются.** Цены, названия, артикулы, применимость,
  адрес продавца — только из таблицы или переменных окружения.
- **`README (3).md` и `tokens.json`** не изменяются без явного указания.
- **Цвета только через токены** (`var(--…)` / утилиты), иначе гейт `hex-color`.
- **Секреты не попадают в репозиторий.**
- **Заглушек и `TODO`/`FIXME` нет** — ESLint `no-warning-comments`;
  неиспользуемые импорты роняют lint. Переменную нельзя назвать `module`.
- **Голос бренда:** коротко, на «вы», без эмодзи и восклицаний, цены
  `17 500 ₸`.
- Каждая задача — коммит на русском с разделами «Сделано:» / «Отменено:».
- **«Готово» только после проверки на проде в браузере**: точный URL и
  что увидено — в отчёт. Зелёные unit-тесты не доказывают UI.
- Стили текста: `t-body`, `t-body-strong`, `t-price`, `t-small`,
  `t-caption` (uppercase), `t-part-number`. У инпутов и кнопок глобальный
  `min-height: var(--space-12)` — для ссылок-кнопок `min-h-0`.

### Ключевые решения и их причины

| Решение | Почему так |
| --- | --- |
| Ключ позиции — колонка `ID`, не артикул | артикула нет у 91 позиции, три дубля |
| Копия таблицы через `IMPORTRANGE` отвергнута | `ID` не переживёт вставку строк в оригинале |
| Цена заказа берётся с сервера по `id` | клиентское значение игнорируется; клиент шлёт только id, qty, предложения |
| Порядок «запись в лист → ссылка WhatsApp» | незаписанный заказ не существует; при отказе Google — 502 без ссылки |
| Telegram через `after()`, `notifyNewOrder` не бросает | заказ уже записан, сбой канала не должен выглядеть как отказ |
| Адреса `/order/:number/print` нет | номера последовательны, перебором открывался бы чужой заказ |
| Админка только читает | источник — таблица; есть сброс кэша, синхронизации нет |
| Печать — HTML + `@media print` | номер на бланке не печатается: присваивается при записи |
| Фильтр марок на сервере | чужие марки не уходят в браузер |

### Технические мелочи

- Node в режиме strip-only TS: ломается на parameter property и
  `server-only`; чистую логику держать отдельно от серверной. Импорты
  между `lib/*.ts` — с расширением `.ts` там, где их грузят тесты.
- `LF will be replaced by CRLF` — норма.
- `styles/tokens.css` генерируется на `prebuild`, руками не правится.
- `.dc.html` из редактора дизайна в репозиторий не кладётся.
- Инструмент `edit`: фрагмент `oldText` должен быть уникален в файле.
